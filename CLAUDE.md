The Stage I review is done (deck: `docs/stage1_deck.md`, original `.pptx` alongside it); **no experiments have been run yet.** We are building a claim-level framework that checks whether an LLM answer in an Indian language is actually supported by the passages retrieved for it, with span-level attribution.

Goals, in priority order:
1. Implement **everything promised in the Stage I deck** (Section 3 is the checklist).
2. Turn it into a **publishable research paper** (Section 4 lists the upgrades this needs).

## 1. The one contract

> The detector never asks "is this true?" — it asks "does the retrieved evidence say this?"

We measure **faithfulness to the retrieved context**, not world factuality. Every claim the system outputs must point back at a specific retrieved passage, or be explicitly marked as having no support. Retrieval scores are carried forward through every stage so a retrieval failure can be told apart from a generation failure.

## 2. Ground rules for working in this repo

- **Plan before code** for anything bigger than ~1 hour. Maintain:
  - `docs/PLAN.md` — current plan + traceability matrix (deck item → module → test → metric)
  - `docs/PROGRESS.md` — dated log of what was done, what broke, what's next
  - `docs/DECISIONS.md` — short ADR-style entries for every non-obvious choice (model, threshold, split, etc.)
  - `docs/RESOURCES.md` — every model/dataset used: exact HF ID, revision, licence, gated?, size, VRAM
- **Never fabricate** numbers, results, citations, paper titles, model IDs or dataset IDs. Before using any Hugging Face model/dataset, verify it exists and record licence + gating in `docs/RESOURCES.md`. If a citation in this file says "verify", check it before putting it in the paper.
- **Every number** that appears in the README, the paper, or a review deck is generated by a script from files in `results/`. No hand-typed results. The deck's `[INSERT …]` placeholders are filled only from measured runs.
- **Reproducibility:** all runs are config-driven (YAML under `configs/`), seeded, with a fixed decoding config. Each run writes `results/runs/<run_id>/` containing the resolved config, git commit hash, model revisions, and outputs.
- **Compute budget:** one 16 GB GPU (Colab/Kaggle T4-class) plus a CPU laptop. Use 4-bit quantisation for 7–10B generators. Cache every LLM generation to JSONL so it is never recomputed. **Ask before** any download > 10 GB or any paid API call.
- **Unicode:** normalise to NFC. Never compute spans on normalised text without an offset map back to the original string — span metrics are computed on original character offsets.
- Never commit to main directly. Work on a feature branch, push it, open a PR with gh pr create (clear title, summary of changes, how it was tested), and wait for the maintainer to review and merge.
- Small, focused commits with clear messages. `pytest` for tests; GitHub Actions runs unit tests on CPU (tiny models or mocks only).
- Python 3.11. Package as `src/indichallu/` with `pyproject.toml`; pin dependencies.
- Keep modules framework-free and testable. LlamaIndex/LangChain (listed in the deck) are used only as a thin orchestration layer for indexing/retrieval — the detector itself does not depend on them.

## 4. Upgrades beyond Stage I (needed for a publishable paper)

### 4.1 Related work the Stage I survey is missing — verify each before citing

| Work | What it does | Why the gap still holds |
|---|---|---|
| **PsiloQA** (2025, arXiv 2510.04849) | Span-level multilingual hallucination dataset, 14 languages incl. Hindi | Answers generated *without* passages — not RAG faithfulness; Hindi is the only Indic language |
| **Mu-SHROOM**, SemEval-2025 Task 3 (`Helsinki-NLP/mu-shroom`) | Span-level hallucination detection, 14 languages incl. Hindi | Closed-book QA, not RAG; one Indic language |
| **BHRAM-IL** (BHASHA workshop @ IJCNLP-AACL 2025, arXiv 2512.01852) | Hallucination benchmark for Hindi, Gujarati, Marathi, Odia + English | Question-level LLM hallucination; not span-level, not grounded in retrieved evidence |
| **IndicRAGSuite** (AI4Bharat, 2025, arXiv 2506.01615) | IndicMSMarco (13 languages) + large Wikipedia-derived RAG training triplets (19 languages) | RAG resource with no hallucination labels — **we use it as data** |
| **LettuceDetect** (2025) + multilingual (EuroBERT) + **v2** (mmBERT-base, arXiv 2607.00895) | Token-level RAG hallucination detector | No Indic training/evaluation — **strong baseline and recipe** |
| **Thoresen & Smart**, RESOURCEFUL 2026 | Synthetic hallucination data via LettuceDetect for 21 European languages | European only — **recipe we adapt to Indic** |
| **Turk-LettuceDetect** (2025, arXiv 2509.17671) | RAGTruth translated to Turkish + fine-tuned detectors | Turkish only — same translation recipe |
| **LM-Polygraph** / Claim-Conditioned Probability (Fadeeva et al. 2024; Vashurin et al., TACL 2025) | Claim-level uncertainty for fact-checking LLM output | Not RAG-faithfulness, not Indic — **white-box baseline** |
| **IndicXNLI** (EMNLP 2022) | NLI data for 11 Indic languages | Training data for our aligner |
| **Nanda family** (EACL 2026) | Open Hindi–English LLMs (10B, 87B) | Use Nanda-10B as a Hindi generator |

**Restated research gap:** no RAG-grounded, span-annotated hallucination resource or detector that targets *multiple* Indic languages — Hindi appears only inside broad multilingual sets, and the Indic hallucination benchmark that exists is not RAG. **Slide 13's bullet "Benchmarks exist for English and for South African languages — not for Indic ones" must be rewritten** before Stage II, because BHRAM-IL now exists. Write `docs/related_work.md` with this table expanded and verified.

### 4.2 Baselines (a paper without these will not be accepted)

- **B1** Off-the-shelf multilingual NLI at sentence level (no decomposition).
- **B2** LettuceDetect v2 mmBERT token classifier, zero-shot.
- **B3** LLM-as-judge (prompted).
- **B4** Uncertainty-based: LM-Polygraph token entropy and CCP from the generator's own logits.
- **B5** Translate-test: IndicTrans2 → English, run an English detector, project spans back.
- **Ours:** decompose → Indic-tuned alignment + typed verifiers → aggregate.

### 4.3 Contributions to aim for (the paper needs at least two)

- **C1 — Resource.** Working name *IndicRAG-Hallu*: a human span-annotated test set for 2–3 languages the team speaks natively (likely Hindi + Marathi + one more), plus a synthetic training set for all languages in scope. Released on HF with a datasheet and licence.
- **C2 — Typed verifiers.** Normalisation-based NUMERICAL and TEMPORAL checkers that handle Indic digit systems, Indic month/day names and date formats; ENTITY/LOCATION checks via IndicNER plus transliteration-aware fuzzy matching. Fuse with NLI scores. Measure where NLI alone fails on numbers.
- **C3 — Indic-tuned aligner.** Fine-tune an encoder (candidates: MuRIL, IndicBERT v2, mmBERT, XLM-R) on IndicXNLI + synthetic claim–evidence pairs; compare against off-the-shelf multilingual NLI.
- **C4 — Controlled retrieval-vs-generation attribution** (objective 05, done causally rather than by correlation). Run the same question under: gold passage only / gold + distractors / distractors only (gold removed) / gold passage machine-translated into English. Measure hallucination rate and detector quality in each condition.
- **C5 — Cross-lingual transfer.** Train on Hindi only; test on Marathi (same script, related), Bengali (related, different script), Tamil/Telugu (Dravidian). Relate the drop to resource level.
- **C6 — Native vs translate-test.** Our detector vs B5 answers whether Indic-native detection is needed at all.

### 4.4 Data plan

- **Contexts / QA:** `ai4bharat/IndicQA` (covers all nine in-scope languages; CC-BY-4.0). Its HF repo uses a loading script that recent `datasets` versions refuse — download `data/indicqa.<lang>.json` directly. IndicRAGSuite Wikipedia triplets for corpus and training; IndicMSMarco for retrieval evaluation. Verify IDs and licences.
- **Generators:** at least three, under one fixed decoding config — e.g. `MBZUAI/Llama-3-Nanda-10B-Chat` (Hindi), a Llama-3.1-8B-Instruct, and a Gemma-3 or Qwen2.5 instruct model. Check gating and licences; 4-bit on 16 GB.
- **Synthetic labelled data:**
  1. *Typed injection* — take faithful answers and inject ENTITY / NUMERICAL / TEMPORAL / LOCATION errors with known spans (IndicNER for entities; script-aware number and date perturbation).
  2. *Translated RAGTruth* — IndicTrans2 with hallucinated spans wrapped in markers; drop items where markers are lost or broken.
  3. *Natural hallucinations* — generator outputs under degraded retrieval (C4 conditions), auto-labelled by an LLM judge, with a human-checked sample to measure the auto-labeller's accuracy.
- **Gold test set:** human annotation of *natural* generator outputs (never injected ones). Write `docs/annotation_guidelines.md` with Hindi examples first. Annotation tool: Label Studio or a small Gradio app writing JSONL with character offsets. Double-annotate at least 20%, report κ/α, adjudicate disagreements.
- **Splits** by passage/question — the same passage never appears in both train and test.
